# PDALSeq_manuscript workflow

Snakemake workflow that processes PDAL-Seq reads and runs every analysis in the manuscript.
Figure and table scripts are run separately (see [Figures and tables](#figures-and-tables)).

All commands are run from this directory (`PDALSeq_manuscript/`), where the Snakefile
expects `PDALseq_samples.txt`.

## Requirements

- Linux with conda (or mamba)
- Snakemake (TODO: version used)
- Per-step software is installed automatically from `workflow/env/*.yml` when run with
  `--use-conda`. Main tools: fastp 0.24.0, BWA 0.7.18, samtools 1.21, bedtools 2.31.1,
  deepTools 3.5.6, UCSC utilities (bedGraphToBigWig, faSize, liftOver), megadepth,
  Python 3.9 (pandas 2.2.3, numpy 2.0.2, hmmlearn, biopython 1.85) and R 4.4.0
  (tidyverse, viridis, ggbeeswarm, ggpubr, cowplot, cluster, mclust, matrixtests, MuMIn).
- Step 06 uses Tandem Repeats Finder 4.09 (`workflow/scripts/06_reference_free_repeat_analysis/trf409.legacylinux64`).
- Resources used for the paper: 20 cores, 120 GB RAM, ~290 GB of inputs.

## Inputs

### Sample sheet: `PDALseq_samples.txt`

Tab-separated, one row per sequencing library (technical replicate). The workflow uses three columns:

| Column | Meaning |
|---|---|
| `Sequencing_sample` | Library name; raw reads are read from `PDALseq_data/Raw_fastq/{Sequencing_sample}.fastq.gz` |
| `Experiment` | Cell line + method (e.g. `Hsapien_GM24385_PDALseq`); technical replicates with the same `Experiment` are merged |
| `Species` | Genome to map to: `resources/genomes/{Species}.fasta` |

Two naming rules are assumed but not checked:

- **`Sequencing_sample` must start with the species name** (`Hsapien_…`, `Ggorilla_…`).
  `map_reads.sh` and `genome_window_coverage.sh` take the genome from the first
  `_`-separated field, so any other prefix silently looks for a genome that does not exist.
- **Reads are processed single-end (R1 only)**, even though libraries were sequenced
  paired-end. Sample names end in `_R1_001`.

Data added during revision (K562, and DMSO-synchronized GM24143/GM24385) is not in the
sample sheet; steps 21 and 25 read it from `Revisions_data/Raw_fastq/` with their own rules.

## Running the workflow

```bash
snakemake -n --use-conda                     # dry run: list jobs
snakemake --use-conda --conda-frontend conda --cores 20 \
    --resources mem_mb=120000                # run
```

**Choosing which steps run.** Each step is a file in `workflow/rules/` included from
`workflow/Snakefile`. To run a step, uncomment its `include:` line and its outputs in
`rule all`. As committed, the Snakefile has steps 12, 14 and 19–30 switched on. Earlier
steps were run first, and later steps read their outputs with `ancient()` so they are not rerun.

Set `--resources mem_mb` well above the memory of a single job. It is a global limit, so a
low value (e.g. 12000 with 8 GB jobs) runs only one job at a time.

To restart after interrupting Snakemake:

```bash
snakemake --unlock
snakemake --use-conda --conda-frontend conda --cores 20 --resources mem_mb=120000 --rerun-incomplete
```

Do not edit an existing `workflow/env/*.yml`. Snakemake hashes each environment file and
reruns every completed job that used it if it changes. Add a new environment file instead.

## Figures and tables

Figure and table scripts are run by hand with R after the workflow, from this directory:

```bash
Rscript workflow/scripts/Revised_figures/Figure_3_Ape_PDAL-Seq_MVGHMM.R
```

They read from `data/` and `results/` and write SVGs to `revised_plots/`, `new_plots/` or
`plots/`. They need R with tidyverse, viridis, cowplot, ggbeeswarm, ggpubr and ggrepel.

[FIGURES.md](FIGURES.md) lists which script makes each figure and SI dataset in the paper.

| Folder | Contents |
|---|---|
| `scripts/Revised_figures/` | Figures as revised during peer review (final versions) |
| `scripts/new_plots/` | Figures from the submitted version that were not revised |
| `scripts/Figures_Tables/` | Figures and SI datasets from earlier drafts; some are still used (see FIGURES.md) |
